# 托育中心运营协同系统

市级统筹用的托育综合服务中心运营协同内核。以**事件溯源 + 版本化规则**管理：
项目节点、场地与班型、全日托/半日托/计时托名额、婴幼儿签约服务包、家长授权与
健康资料共享、人员培训调班、消防/食品/伤害预防检查整改、社区活动、收费减免、
转介与监督回执。

## 设计要点（对应落地难点）

| 难点 | 做法 |
| --- | --- |
| 竣工延期不能连带停摆社区点位 | 延期是 `site:{本点位}` 流内事件，不存在全市级冻结；网络视图按点位各自状态折叠（`tests/postponement.test.js`） |
| 竣工后一年内运营 | 竣工事件算出 `operateBy = 竣工日+1年`；逾期允许开业但打 `overdue` 标记供督办，事实不抹除 |
| 计时托跨午夜/改期按实际时段结算 | 结算只认签到-签退折叠出的实际分钟数（`clock.actualServiceMinutes`），跨午夜分段标注并加夜间附加；改期追加事件、原预约保留，账单盖当时规则版本 |
| 名额真实可预约 | 家庭视图同时联查 点位运营状态 + 容量占用 + 持证保育配备，超售在命令阶段拒绝，取消即时释放 |
| 健康资料最小授权 | 共享必须命中"对承担服务机构、该用途、仍有效"的授权；他机构/过期/撤回一律拒绝 |
| 撤回授权的两种语义 | 撤回时未用于照护的记录立即 `CLOSED` 停共享；已形成安全/医疗记录的不抹去，只能追加 `HEALTH_RECORD_CORRECTED` 更正 |
| 断网签到/重复扣费/调班/回执乱序 | 事件 `event_id` 全局幂等；状态按 `occurred_at` 业务时间折叠（乱序收敛）；流内 `version` 乐观并发拒绝过期调班；监管回执阶段守卫 + 回执号幂等 |
| 看出决定基于哪版规则 | `RuleBook` 不可变版本化，每个决定事件盖 `rule_version`，`ruleProvenance` 可逐条溯源（名额、照护决定、整改结论、账单） |

## 结构

```
contracts/event.schema.json   事件信封合同
src/
  contract.js                 信封校验
  clock.js                    时区/实际服务时段/跨午夜/一年期限
  rulebook.js                 不可变版本化规则库
  store.js                    按主体隔离的幂等事件存储（乐观并发）
  relay.js                    断网 outbox：乱序/重复安全回放
  system.js                   门面：dispatch 盖章规则版本、折叠、落库；计时托结算工作流
  readmodels.js               家庭可预约 / 市级1+N网络 / 规则溯源 / 授权台账 / 账单视图
  domain/
    site.js                   项目节点、点位类型(CENTER/COMMUNITY/EMPLOYER)、延期、开业、妇幼协议
    catalog.js                场地班型与名额、预约/确认/改期/释放
    agreement.js              签约、家长授权、健康共享/撤回/更正、考勤、照护决定、转介
    staff.js                  人员资质培训、排班调班、配备核算
    inspection.js             消防/食品/伤害预防检查、整改通知、监管回执、归档
    billing.js                账单、幂等扣费、减免调整、计时托计费
    activity.js               社区活动与报名
tests/                        覆盖上述每条硬规则的场景测试
```

## 主体流（subject_id）

`site:` `catalog:` `child:` `staff:` `inspection:` `billing:` `activity:` 各成独立
事件流，流间只通过读模型联查、不共享可变状态——这是"延期爆炸半径不扩散"的结构保证。

## 事件溯源约定

- 事件**只追加、不可变**；更正/退减/调班都用新事件表达。
- 聚合为纯函数：`apply(state, event)` 与 `decide(state, command)`，无副作用、可重放。
- 每条领域事件携带 `rule_version`；规则改动发新版本并带生效日，旧决定永远指向旧规则。
